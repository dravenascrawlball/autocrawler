# Working with this project

## Feature workflow

Don't start implementing a roadmap item just because it's queued up next.
The process for each new feature is:

1. User names the next feature to work on (usually the next item in
   `docs/roadmap.md`).
2. Claude asks open questions about it first — design decisions, scope
   boundaries, anything ambiguous about how it should behave — and we
   discuss until the shape of the feature is clear.
3. Only then does implementation start.

This applies to roadmap items and any other non-trivial feature request.
Small, unambiguous asks (bug fixes, one-line tweaks) don't need this.
